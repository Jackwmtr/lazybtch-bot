# LazyBTch Bot — дизайн

Бот-транскрибер для Telegram: пересылаешь (или кидаешь) боту голосовое — он возвращает текст.
Движок: **Groq** (`whisper-large-v3-turbo`). Каждый пользователь привязывает **свой** `GROQ_API_KEY` при первом обращении.

---

## 1. Цели и не-цели

### Цели
- Минимальное UX: forward голосового → получить текст, без лишней настройки.
- Per-user ключи Groq: бот не держит чужие лимиты, стоимость прозрачна для пользователя.
- Надёжность: кэш, ретраи, понятные ошибки («у тебя нет ключа», «файл слишком большой»).
- Дёшево в эксплуатации: однопроцессный, SQLite, без внешних зависимостей кроме Groq API.

### Не цели (v1)
- Не MTProto-бот (не читает чаты напрямую) — только то, что пользователь сам переслал боту.
- Не локальный Whisper (Ollama и т.п.) — v2, если Groq станет неудобным.
- Не транскрипция видео/видео-кружков в v1 (технически то же аудио — оставить хук, но не обещать).
- Не мультиаккаунты, не группы-фичи сверх «бот в группе, куда кидают голосовые».

## 2. Сценарии

### 2.1 Первый запуск (onboarding)
1. Пользователь пишет боту `/start` (или просто кидает голосовое).
2. Бот отвечает инструкцией: «Перешли голосовое, и я верну текст. Для начала нужен твой ключ Groq — бесплатно за 2 минуты на [console.groq.com](https://console.groq.com)».
3. Пользователь: `/key gsk_...`
4. Бот: валидирует ключ (лёгкий запрос к Groq, напр. `GET /openai/v1/models`), хранит зашифрованным, отвечает «Ключ сохранён ✅». Ключ в ответе больше **никогда не печатает**, только маска `gsk_a1…fZ`.

### 2.2 Обычный запрос
1. Пользователь пересылает (forward) голосовое или видео-кружок в чат с ботом (или боту в группе).
2. Бот:
   - скачивает файл через Bot API (`getFile` → URL → HTTP GET),
   - транскрибирует через Groq,
   - отвечает текстом с метаданными: `🎙 [3 сек, ru] Передаю привет на конверте.`
3. Ответ идёт как reply к исходному сообщению (в группе видно, к чему относится).

### 2.3 Ошибки
| Ситуация | Реакция бота |
|---|---|
| Нет ключа | «У меня ещё нет твоего ключа Groq. `/key gsk_...` — и попробуй ещё раз» (сообщение не теряется: повторный forward сразу транскрибирует) |
| Ключ невалиден / 401 | «Ключ не сработал (401). Проверь: `/key <новый>`» |
| Квота/лимит Groq (429) | «Groq жжёт лимит, подожди ~минуту и перешли ещё раз» + не спамим retry |
| Файл > 25 МБ (free tier) | «Это 47 МБ — выше лимита Groq free tier (25 МБ). Попробуй разрезать или платный тариф» |
| Не голосовое (фото/документ/видео без аудио) | «Я понимаю только голосовые и кружки 🙂» |
| Пустая расшифровка | «Расшифровка пустая — похоже, в записи нет речи» |
| Таймаут Groq | «Groq не ответил за 60с, попробуй ещё раз» |

### 2.4 Команды
| Команда | Действие |
|---|---|
| `/start` | onboarding + статус (ключ есть/нет, язык) |
| `/key gsk_...` | сохранить/заменить ключ (валидация + шифрование) |
| `/key off` | удалить ключ |
| `/lang <code>` | задать язык для записи (по умолчанию autodetect). Аргумент `auto` возвращает автоопределение |
| `/stats` | кол-во транскрипций, суммарная длительность, последние N ошибок (без аудио в логах) |
| `/help` | краткая справка |

Голосовое = «команда по умолчанию»: любое аудио-сообщение в чате с ботом (в т.ч. forward, в т.ч. из группы) трiggert транскрипцию. Без команд.

## 3. Архитектура

```
 Telegram ⇄ Bot API (long polling)
                │
        ┌───────▼────────┐
        │   Бот (Python) │  единый процесс
        │  aiogram 2.x   │
        └───────┬────────┘
                │
   ┌────────────┼─────────────────────┐
   │            │                     │
┌──▼─────┐ ┌───▼──────┐ ┌────────────▼────────┐
│ SQLite │ │ Crypto   │ │ Groq Client         │
│ users  │ │ (Fernet) │ │ whisper-large-v3-   │
│ cache  │ │ keys     │ │ turbo, httpx        │
└────────┘ └──────────┘ └─────────────────────┘
```

Один процесс, три слоя:

1. **Транспорт** — aiogram, long polling (без вебхуков/домена/TLS). В группе бот слушает только: прямые сообщения ему (@bot в упор), forward-нутые ему сообщения и audio/video_note, пришедшие в общий поток.
2. **Домеn** — `Transcriber`: скачивание → лимиты → Groq → постобработка. Stateless, принимает `bytes + mime + user_ctx`.
3. **Хранилище** — SQLite (WAL): `users`, `transcripts` (кэш), `events` (мелкая статистика).

### Почему aiogram, а не python-telegram-bot / raw Bot API
- Асинхронный, зрелый, типизированный; удобные хендлеры под ContentType (audio, voice, video_note) и сервисные/forwarded сообщения.
- (Альтернатива ptpb v20+ — ок, но aiogram привычнее и стабильнее по API.)

## 4. Данные

### Таблицы

```sql
CREATE TABLE users (
  user_id     INTEGER PRIMARY KEY,      -- telegram user id
  username    TEXT,
  groq_key    TEXT,                     -- Fernet-шифрованный blob, НИКОГДА не plaintext в БД
  lang        TEXT DEFAULT 'auto',      -- 'auto' | 'ru' | 'en' | ...
  created_at  TEXT DEFAULT (datetime('now')),
  updated_at  TEXT
);

CREATE TABLE transcripts (              -- кэш, чтобы повторный forward не платил Groq
  content_hash TEXT PRIMARY KEY,        -- sha256(audio bytes)
  user_id      INTEGER,
  lang         TEXT,
  duration_s   INTEGER,
  text         TEXT,
  created_at   TEXT DEFAULT (datetime('now')),
  hits         INTEGER DEFAULT 1
);
-- TTL: выметать записи старше 7 дней (audio не храним, только текст)

CREATE TABLE events (                    -- для /stats и дебага
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER, kind TEXT,           -- 'ok' | 'no_key' | 'groq_401' | 'too_large' | ...
  detail TEXT,                          -- без текста аудио и ключей
  ts TEXT DEFAULT (datetime('now'))
);
```

### Шифрование ключей
- `cryptography.Fernet`, мастер-ключ из env `ENCRYPTION_KEY` (генерация: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`).
- Ключ в лог, в ответы, в events — **никогда**. Только маска `gsk_ab…xy`.
- Ключ в `/key` приходит в открытом сообщении — предупреждать в онбординге: «отправь с `/key`, я его не цитирую дальше; при желании отправь и удали сообщение».

### Кэш
- Ключ — `sha256` аудио-байт + язык (если задан явно). Forward одного и того же сообщения разным людьми = одна оплата Groq.
- Кэш игнорируется, если пользователь явно добавил `--fresh` в forward? Нет — v1 без флага, кэш всегда. Если нужен «переслушать» — это редкость, v2.

## 5. Интеграция с Groq

```
POST https://api.groq.com/openai/v1/audio/transcriptions
Authorization: Bearer <user key>
multipart/form-data:
  model = whisper-large-v3-turbo
  file  = ("voice.<ext>", bytes, mime)
  language = <user.lang>   # только если != 'auto'
```

### Известная грабли (наш опыт, обязательно учесть)
- **Расширение файла**: Telegram голосовые = `.oga` (Opus in Ogg). Groq **отклоняет** `oga` с 400 `unsupported_audio_format`. Загружать как `.ogg` — работает. (См. issue chigwell/telegram-mcp#219.)
- Лимит free tier: 25 МБ на файл — отсечь **до** загрузки/отправки.
- Таймаут HTTP: 60 c. Ретраи: не делаем автоматически (429/5xx → сказать пользователю; автоматические retry на платном action опасны двойной оплатой).
- Ответ `text` может быть пустым → отдельное сообщение «речи не найдено».

### Лимиты бота (Bot API)
- Скачать файл ≤ 20 МБ через `getFile` (лимит ботов). Это жёсткий потолок, выше — только «слишком большой».
- Long polling: один инстанс на один токен.

## 6. Безопасность

1. **Ключи**: Fernet в SQLite, файл БД с правами 0600; `ENCRYPTION_KEY` только в env/secret manager.
2. **Аудио на диске**: не пишем в каталоги; качаем в память (bytes). Единственный вариант на диске — временный файл с `O_TMPFILE`/temp + мгновенное удаление. Аудио **никогда** в логах, кэш = только текст.
3. **Логирование**: structured logs (loguru), запрещённые поля: audio, key, transcript-текст в DEBUG выводить можно, в WARNING/ERROR — нет.
4. **Изоляция пользователей**: ключ юзера A не используется для запросов юзера B (в коде `transcribe(user, audio)` — ключ всегда из контекста user_id, не из глобала).
5. **Бот в группах**: транскрибируем аудио в группе только если бот упомянут/ему переслали, чтобы не спамить чужими расшифровками в чужих чатах (политика настраивается env `GROUP_POLICY=off|mentions|all`, дефолт `mentions`).
6. **Prompt/инъекции**: бот не LLM-агент, только API транскрипции — вектора инъекций нет.

## 7. UX / тексты (черновик)

```
/start:
  🎙 LazyBTch. Перешли мне голосовое — верну текст.
  Для начала привяжи свой ключ Groq (бесплатно, console.groq.com):
  /key gsk_...
  Я ключ не цитирую и хранишь шифрованным.

без ключа + forward:
  У меня нет твоего ключа Groq. Сдай /key gsk_... и перешли запись ещё раз —
  я её не потеряю, повторная расшифровка уже бесплатно (кэш).

успех:
  🎙 [5 сек, ru]
  Пришли два сапожника к третьему сапожнику…

  (reply к исходному сообщению; в группе — с цитатой)
```

Стиль: короткий, без «Конечно!», одна строка метаданных + текст. Длинные (>4096 символов) транскрипты резать по 4096 с «…продолжение» в следующем сообщении (лимит Telegram).

## 9. Деплой

### Ключевое свойство
Бот на **long polling**: входящие порты **не нужны вообще** (ни 443, ни 80). Выходное соединение к `api.telegram.org`. Если в будущем появится webhook/UI — порт задаётся env `LAZYBTCH_PORT` (дефолт 8321, легко сменить), наружу публикуется только он.

### Целевой хост (v1)
VPS Ubuntu 22.04, 1 vCPU / 705 МБ RAM / 1.7 ГБ free, Docker 27.5. Бот — ещё один контейнер рядом с существующей инфраструктурой.

### Docker (единственный вариант деплоя)
Переносим на любой дистрибутив с docker:

```yaml
# docker-compose.yml
services:
  lazybtch:
    build: .
    restart: always
    env_file: .env               # BOT_TOKEN, ENCRYPTION_KEY, GROUP_POLICY
    volumes:
      - ./data:/app/data          # SQLite (users, transcripts, events)
    # ports: [] — long polling, наружу ничего не публикуем
```

`Dockerfile`: `python:3.12-slim` → копировать uv → `uv sync --frozen` → `uv run lazybtch`. Image ~150–200 МБ.

Обновление: `git pull && docker compose up -d --build` (бот «мёртв» на время rebuild ~30 c).

### Общие
- Секреты: `BOT_TOKEN` (@BotFather), `ENCRYPTION_KEY` — только в env/`.env` (0600), не в репозитории.
- State = один SQLite-файл в `data/` — перенос на другой хост/дистрибутив = скопировать файл + 2 секрета.
- Мониторинг (v1): `docker ps` / `docker compose logs -f`; бот сам пишет heartbeat-лог раз в час + event `poll_alive`.
- RAM-бюджет: процесс ~120–150 МБ; на целевой ВМ (705 МБ RAM + 767 МБ swap) — ок.

**Критерий переноса**: новый хост = любой Linux с docker + `git clone && .env && docker compose up -d`.

## 10. Тесты

- **Unit**: `groq.py` — маппинг расширений (oga→ogg!), лимиты по размеру, пустой transcript; `crypto.py` — encrypt/roundtrip/маска; `store.py` — кэш-hit/miss, TTL.
- **Интеграционный (мок Groq)**: httpx MockTransport: 200/401/429/400/пустой текст → правильные реакции бота.
- **E2E (ручной чеклист)**: `/start` → `/key` (валидный/битый) → forward голосового (нового/повторного) → `/lang ru` → `/stats` → forward фото (refusal) → forward 30МБ (too_large).
- Тесты не ходят в реальный Groq (ключ из env `GROQ_TEST_KEY` — опционально, CI без него).

## 12. Решения по открытым вопросам (закрыто)

1. **Бот создан**: `@lazybtch_bot`. Токен — только в `.env` на хосте (gitignored), в репозиторий/логи/дизайн **не попадает**.
2. **Группы**: не приоритет. Реализуем как дешёвую часть M4 (политика `mentions`), но не блокируем v1 на них; при желании выкидывается целиком без влияния на ядро.
3. **Кэш transcript**: да, храним текст в SQLite 7 дней (TTL-cleanup) — согласовано.
4. **Биллинг**: v1 — только счётчики в `/stats` (кол-во/длительность); Groq биллинг в API не отдаёт, прокси по duration оставить как есть.
